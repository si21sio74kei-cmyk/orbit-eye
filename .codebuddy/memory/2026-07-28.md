## 3D 地球(遥测页)两个问题修复

用户反馈：(1) 3D 地球会自动"跳到澳门上方"；(2) 希望澳门红点与空间站绿点之间加连线，方便查看两站关系。

排查 `static/js/dashboard.js` 的 `initGlobe`(216) / `updGlobe`(236)：
- **相机无硬编码跳变指令**。根因：第 221 行 `ctrl.autoRotate=true` 自动旋转，周期性把固定在澳门的红点(lon 113.5°E)转到画面正中央，造成"跳到澳门"的观感。修复：`autoRotate=false` + `enablePan=false` + `ctrl.target.set(0,0,0)`，视图稳定。
- **连线其实已存在**(`al` 第 231 行创建，`updGlobe` 第 239 行用 QuadraticBezierCurve3 在澳门 mp 与空间站 ip 间画线)。但原样式为绿色 `0x34d399`、透明度仅 0.4 且受地球深度遮挡，几乎看不见。修复：改为天蓝 `0x38bdf8`、opacity 0.8、`depthTest:false, depthWrite:false`、`renderOrder=3`，穿透地球始终可见，明确呈现两站连线。

验证：`node --check static/js/dashboard.js` 通过；read_lints 0 诊断。已 `git add` 单文件提交并 push，Vercel 会重部署。

注：经纬度→三维坐标用 `llv(lat,lon,r)`(214 行)标准映射；地球半径 1.4，标记在 1.41/1.43，连线控制点凸到 1.50。

## 空间站接口"跳到澳门"根因 + 修复（用户自己猜中）

用户问"是不是空间站 API 的问题"——确实如此。原 `api_iss` 的兜底（demo）把 `iss_position` 硬编码成 `(22.3512, 114.0873)`，即**香港上空、紧贴澳门**。一旦实时接口失败/超时，前端绿点就瞬移到澳门旁边，看着像地球"跳到澳门"。原数据源是 HTTP 的 `api.open-notify.org/iss-now.json`，Vercel 上易超时触发兜底。

修复（`Space_Data_Center.py` 的 `/api/space/iss`）：
- 数据源改为 HTTPS 的 `https://api.wheretheiss.at/v1/satellites/25544`（专为 ISS，稳定，返回 `{latitude,longitude,timestamp}`）。
- 新增模块级 `last_iss` 缓存（小写避免 basedpyright 常量重定义误报）；实时成功则存入，`global` 重赋合法。
- 实时失败 → 复用 `last_iss` 真实坐标（`_source:"cached"`），绿点留在真实轨道，不跳澳门。
- 仅在从未取到实时数据时才用澳门演示兜底（`_source:"demo"`，保留澳门测控链路演示卡）。
- 抽出 `_build_iss(lat,lon,ts,src)` 构造响应，避免直播/缓存重复代码。

验证：`app.test_client().get('/api/space/iss')` → `200 / _source=live / iss=真实坐标 / macao_dsn 距离正确`。已提交推送，Vercel 重部署。lint 的 ERROR 均为项目原有 basedpyright 动态类型推断警告（非语法错误，不影响运行）。

## 线上 Vercel 实测 + 太阳系信息卡 planet-info 兜底修复

用户已部署到 Vercel：`https://orbit-eye-cmyk.vercel.app/`。并发实测线上 API：
- 正常 live/可用：`/iss`、`/apod`、`/exoplanets`、`/satellites`(celestrak)、`/` 页面。
- **仍 demo/error 的两个数据源**：`/solar-storm`(NOAA `services.swpc.noaa.gov`)与 `/planet-info?planet=mars`(le-systeme `api.le-systeme-solaire.net`)。本以为 Vercel 美国服务器能取到，实测也失败——是这两个**特定源对自动化/云请求拒绝**（非地域问题）。`safe_fetch` 本身无问题（其他接口均 live）。

修复 `planet-info`（`Space_Data_Center.py`）：
- 新增 `PLANET_FALLBACK`(小写英文名键，含太阳+八大行星的真实物理参数：meanRadius/mass/sideralOrbit/sideralRotation/axialTilt/gravity/density/avgTemp/escape/moons，字段对齐 `_format_planet_info`)。
- 新增 `REV_MAP`(英文→中文)与 `_planet_fallback(planet)` 助手：统一小写查表、中英文/大小写都能匹配、回显中文名。
- `api_planet_info` 改为：① 近期 le-systeme 失败(`SOLAR_FAIL` 10min 内)直接走本地兜底，避免每次卡 8~15s；② 最终兜底用 `PLANET_FALLBACK` 返回真实数据(`source:"local-cache"`)，不再返回"API 暂时不可用"错误。
- `SOLAR_FAIL` 记录最近失败时间；le-systeme 尝试 timeout 15→10。

坑：前端 `solar.js` 调 `planet-info?planet=` 传的是**小写英文名**(`mars`/`earth`)，初始兜底键用中文/大写首字母导致匹配不上→error。已统一小写键 + `en.lower()` 查表解决。实测中文名、小写英文名均 `local-cache` 即时返回真实数据。

验证：写临时 `test_planet.py` 输出到文件(Out-String 管道会吞 stdout，故改用文件法)，确认全部 local-cache 且显示中文分类正确。已提交 `26fcf4c` 推送，Vercel 重部署。lint 警告均为项目原有 basedpyright 风格，非运行错误。
